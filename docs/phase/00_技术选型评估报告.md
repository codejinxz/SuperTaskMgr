## 〇、产品定位声明（评分轴基准）

**本产品定位为"面向系统管理员的本地自用工具"**：数据密度、采集正确性、低自开销、便携零依赖优先；消费级观感、无障碍/屏幕阅读器、自动化脚本接口为**非目标**。八维评分均以此为轴。敏感度分析：即使按最严苛审查意见（V2）下调 ImGui 的 UI/维护维度，修正后约 4.50-4.65，仍高于 Qt 4.20；决策对权重扰动稳健。

## 一、结论先行

**首选：原生 Win32（窗口/消息循环/托盘/公共对话框）+ Dear ImGui 最新稳定版（master 固定 tag，源码 vendoring）+ D3D11 + ImPlot 全自绘 UI，页签式布局（不依赖 docking 分支），配纯 C++ 无 UI 依赖采集层。**（勘误 v2.1：master 分支无多视口/ViewportsEnable，悬浮窗不能按原设想实现；已改为"暂缓或阶段 3 另行评估独立顶层窗口方案"，见架构文档 §8。此为 D3 开发期实证发现。）
**备选：Qt 6 Widgets（6.8 LTS，LGPL 动态链接）**——触发条件：无障碍/原生观感/输入法成为硬需求。注意该切换等于 UI 层全量重写（约 40% 工程量），采集层原样复用。
明确不推荐（本场景）：WinUI 3（2.98）、Avalonia（3.64）、Tauri（2.87）。

## 三、逐路线优劣摘要

### 胜出：Win32 + Dear ImGui + D3D11 + ImPlot（4.75）
- 优势：POD 快照直供立即模式 UI，采集层零胶水；ListClipper 官方口径数万行、ImPlot 数千点@1Hz 无压力；单 exe 约 2-5MB、零第三方 DLL；双 MIT；提权无框架约束；源码 vendoring 离线可复现。
- 劣势（诚实声明，均为知情接受或已列缓解）：非原生观感；无障碍/UIA 不可用（imgui #8022，定位声明下接受）；中文 IME 输入框有边角细节（阶段 2 spike 实测）；1.92 系动态字体为近年最大破坏性变更，须按 1.92+ API 写代码；排序/列宽持久化、右键菜单等控件细节需自建（ImGui 内建能力覆盖，见 §四成本清单）。

### 备选：Qt 6 Widgets（4.20）
- 优势：Model/View 虚拟化一等公民；暗色/HiDPI/中文开箱即用；6.8 LTS 至 2029。
- 劣势：图表许可陷阱（QtCharts 仅 GPL 且 6.10 起 deprecated；QCustomPlot GPL+商业；KDChart 3.x 已转 MIT 但加依赖）；LGPL 动态链接义务链；便携 50-80MB；获取成本高（无 pip → aqtinstall 不可用；**可 curl 直下官方 .7z 归档或装便携 Python 解决，路径未断裂但成本仍高**；vcpkg 源码编译 1-2h/30GB）；空载内存 30-60MB。
- QtCharts 补注：自 Qt 6.10 起官方废弃（转 Qt Graphs），6.8 LTS 内可用。

### 否决：WinUI 3（2.98）
CMake 不可行（XAML 编译链 MSBuild-only，微软官方确认）；无官方 DataGrid 且 C++ 可用社区表格几乎为零；MSIX 提权受限，仅"非打包+自包含"勉强可行；自身体积/内存与资源监控器定位自相矛盾。

### 否决：Avalonia（3.64）/ Tauri（2.87）
- Avalonia：Win11 不预装 .NET 桌面运行时 → self-contained 数十至 150MB；NativeAOT 与 DataGrid 反射、C++/CLI 三者互斥；托管+原生双层调试。
- Tauri：sysinfo 0.39 无按进程网络/句柄/服务/启动项，约半数采集需求仍需 Rust 重写；1Hz×500 行需自建二进制 IPC 绕 JSON 慢路径；C++ 采集资产近乎全弃。

## 四、仲裁依据与自绘成本清单

ImGui 胜出四因：① 任务管理器类工具是其原生主场（定位声明下，Qt 的观感/无障碍优势贬值）；② 构建现实（pip 缺失、Qt 二进制 1-2GB 级获取成本 vs vendoring 2MB 秒级编译）；③ POD 快照零拷贝直供；④ 双 MIT + 单 exe 最小分发面。
**自绘成本两栏（V2 修正）**：ImGui 内建直接可用——表格排序/列宽/行选中/右键菜单/页签/拖拽/文本过滤/Plot 滚动窗口/暗色主题变量；需自建——原生菜单与托盘集成（Win32 侧）、确认对话框（模态封装）、悬浮窗（多视口）、中文 IME 细节调校、主题跟随系统（注册表读取）、WARP/限帧兜底策略。

## 五、采集层技术基线（UI 无关，直接进入阶段 1）

| 功能 | 选定 API/方案 | 权限 | 关键对策 |
|---|---|---|---|
| 进程枚举+CPU/IO/句柄/线程/父链/缺页 | NtQuerySystemInformation(SystemProcessInformation) 一次取全 | 无特权 | **三层降级链**：NtQSI → 启动时字段偏移自校验门（与 GetProcessTimes/GetProcessMemoryInfo 交叉比对，失败自动降级）→ Toolhelp+PSAPI 文档化慢路径（注：Toolhelp 无 CPU/IO/句柄数，慢路径仅保基础枚举） |
| 进程身份 | (PID, CreateTime) 二元组；26100+ 用 SequenceNumber | — | 防PID复用竞态 |
| 内存三项 | GetProcessMemoryInfo + PROCESS_MEMORY_COUNTERS_EX | QLI | PrivateUsage=私有提交 |
| 每核 CPU / 上下文切换 | NtQSI SystemProcessorPerformanceInformation + 线程结构聚合 | 无特权 | 半文档化字段进自校验门 |
| GDI/USER 句柄 | GetGuiResources（选中进程按需取） | QLI | 文档化 |
| 提权/UWP/WOW64 标记 | TokenElevation / GetPackageFullName / IsWow64Process2 | QLI | 按需取+缓存 |
| 命令行/窗口标题/用户名 | PEB 读取（需 VM_READ，按需+降级）/ EnumWindows 映射 / token 按需 | 视权限 | 普通权限取不到即留空 |
| 映像路径 | QueryFullProcessImageNameW；PPL 失败时 NtQSI ImageName；UWP 加包名 | QLI | 降级正常 |
| 签名校验 | WinVerifyTrust（VERIFY 必配 STATEACTION_CLOSE；catalog 路径；结果缓存） | 无特权 | 吊销检查默认离线 |
| 终止/树杀 | SeDebugPrivilege+TerminateProcess；树杀按身份快照自底向上；服务进程先停服务（QueryServiceStatusEx dwProcessId） | 提权 | 保护名单：System(4)/Idle(0)/smss/csrss/wininit/winlogon/services/lsass/Registry/Memory Compression/dwm；交互层二次确认 + Ops 层硬拒绝双层防线 |
| 内存清理 | EmptyWorkingSet/SetProcessWorkingSetSize；NtSetSystemInformation(MemoryPurgeStandbyList) | 提权（后者 SeProfileSingleProcessPrivilege） | UI 明示局限（缺页代价/只清缓存）；Hard Faults/sec 作为代价度量仪表 |
| 按进程磁盘 | PDH \Process(*)\IO Data Bytes/sec（口径=文件+网络+设备总和，如实标注）；ETW 精确版为提权增强 | 无特权 | PdhAddEnglishCounterW（本机实测可用）；通配符手动展开+ID Process 实例映射 |
| 网络 | GetExtendedTcp/UdpTable(OWNER_PID)；流量=ETW Kernel-Network（提权增强，显式开关，会话命名+退出清理） | 连接表普通权限 | OWNER_MODULE 非管理员为空，标注 |
| GPU | PDH GPU Engine / GPU Process Memory / GPU Adapter Memory（本机实测非管理员可读）；DXGI 枚举适配器，**过滤虚拟显示适配器**（IddCx 类） | 无特权 | 实例名 pid_<pid> 半文档化解析聚合；虚拟适配器过滤进阶段 1 验证项 |
| 传感器 | 方案A：CallNtPowerInformation+PDH（频率/占用，全）、IOCTL_STORAGE 协议路径（SMART，全，限直连盘，管理员）、MSAcpi_ThermalZoneTemperature（**标注为"ACPI 热区温度"而非 CPU 核心温度**，管理员，主板支持面不一）、IGCL/NVML/ADLX（GPU 温度/风扇，视厂商驱动组件，用户态） | 见左 | 方案B（PawnIO / LibreHardwareMonitor sidecar）仅文档化路线，不随包分发；厂商 SDK 头文件**不进仓库**（构建说明指引下载）；拿不到的显示"需要驱动/管理员支持"，绝不显示假数据 |

## 六、提权模型技术落点（1A，V3-P0 修复）

1. manifest：`asInvoker`；提权动作经 `ShellExecuteExW(lpVerb=L"runas")` 重启自身（处理 ERROR_CANCELLED 静默回退）。
2. 单实例：命名互斥体 `Local\SuperTaskMgr.SingleInstance`；重启握手：旧实例持久化会话状态（选中页签、选中进程 (PID,CreateTime)、窗口位置）→ 触发命名事件 → 退出释放互斥体；新实例等待互斥体获取 + 事件后恢复状态。
3. 功能×权限矩阵（普通权限可用 / 提权增强 / 仅提权）在架构文档《进程模型与提权》章节固化，并驱动 UI 的"需提权"徽标。
4. SeDebugPrivilege 用后即释（仅提权实例内按需启用）；提权实例不写任何自启动项、不留常驻服务（合规约束：无持久化）。

## 八、合规与安全工程化（V2-P1 修复）

- README 必含声明：本工具未签名，SmartScreen/AV 可能告警（附"为什么不签名"说明）；ETW 仅在用户显式开启时启动且会话名唯一、退出必 StopTrace；所有操作有日志（%LOCALAPPDATA% 下滚动日志，可审计）。
- 破坏性操作（杀进程/树、清内存、禁服务/启动项）一律二次确认 + 保护名单硬拒绝双层防线。
- 启动项禁用操作前自动导出原值备份（.reg/JSON）到日志目录，保证可逆。
- 不含任何隐蔽、持久化、规避检测能力；自身不自启动、不留服务、不联网上传（吊销检查默认离线）。
- Unicode 工程规范：全宽字符 API、`/utf-8`、`std::wstring` 边界、长路径（`\\?\`）策略、中文路径冒烟用例入自测。

## 九、风险与缓解

1. ImGui 上游断裂/升级风险 → 固定 tag+哈希，升级走显式评审；图表降级方案：ImPlot 不可用时自绘简单折线（已评估可行）。
2. NtQSI 半文档化 → 启动自校验门 + Toolhelp 慢路径双保险（§五）。
3. PDH 本地化 → PdhAddEnglishCounterW 全覆盖（本机实测）；实例歧义用 ID Process 映射。
4. 无障碍缺失 → 定位声明 + Qt 备选路线（代价：UI 全量重写，已如实标注）。
5. 传感器覆盖不足（本机 Intel 核显）→ 厂商 SDK 缺失时诚实降级；ACPI 热区命名校正。
6. 未签名分发告警 → README 说明 + 日志审计透明化。
