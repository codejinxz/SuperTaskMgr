## 一、用户报告 bug 的根因与修复（F1 实证）

| Bug | 根因（文件:行） | 修复 |
|---|---|---|
| 终止进程/树/释放工作集/清待机 无反应 | 确认模态被 `confirmOpenRequested` 门控**只在单帧渲染**（~16ms）：永远收不到点击，且残留"僵尸模态"吞掉后续悬停/点击（Pages.cpp:314 旧逻辑） | DrawConfirmDialogs 重写：OpenPopup 一次、BeginPopupModal 每帧执行、Esc/取消/确认全路径清状态 |
| 启动项（及服务页）确认禁用无反应 | 模态内**每帧** `SetKeyboardFocusHere(0)`：导航重提交在按下与抬起之间偷走鼠标按住按钮的 ActiveId（imgui.cpp:14402 ClearActiveID）→ 点击被静默吞掉 | focus 仅 `IsWindowAppearing()` 时调用一次；确认动作统一走 ConfirmAction.h（shared_ptr 捕获、失败必有 toast） |

实证方式：无头 ImGui 事件注入 harness 复现旧缺陷（submitKill=0）→ 修复后 PASS；产品化为 `--autotest dialogclick`（真实 NewFrame 管线注入鼠标、断言子进程退出与模态关闭、含"模态单帧化"哨兵——旧 bug 复原时 FAIL，双向验证守卫有效）。V14 独立复核判定 PASS：三链路状态机干净、连点无双杀、plan 失败有红 toast。

## 四、F4 功能评估结论（docs/phase/05_feature_recs_F4.md）

- **已实现（快赢）**：模块列表 UI + 按模块签名校验（数据早已采集，仅差渲染）。
