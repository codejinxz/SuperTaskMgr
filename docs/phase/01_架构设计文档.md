## 1. 目标与定位

- 产品：Windows 超级任务管理器（codename `SuperTaskMgr`），面向系统管理员的本地自用工具。
- 平台：Windows 10 21H2+ / Windows 11 x64，仅 x64；技术栈 Win32 + Dear ImGui(master 稳定 tag) + D3D11 + ImPlot + 纯 C++ 采集层；C++20；MSVC /W4 /utf-8 /MT；CMake ≥3.20。
- 硬约束：破坏性操作二次确认+关键进程保护名单双层防线；文档化 API 优先（半文档化必须自校验+降级）；高频采样不拖慢系统；UI 永不阻塞；全 Unicode；无隐蔽/持久化/规避检测能力。

## 2. 总体架构与分层

```
UI 线程(1)：App(消息循环) → D3DRenderer+ImGuiBackend → IPage 页签(进程/性能/…)
             每帧: SnapshotStore::Get() 读取；NotificationQueue 轮询取操作结果
  ↑ shared_ptr<const Snapshot>（1Hz）          ↑ JobQueue 提交 / 结果经 NotificationQueue
采集线程(1)：CollectService→Process/System/Gpu Collector → SnapshotStore   操作线程(1)：OpsWorker(JobQueue 串行)
公共层 stm_core：ProcData(契约)/Log/Str/Err/Cfg/Jobs/Notifications/ProcKey
操作层 stm_ops：ProtectedList/ProcessOps/Signature/Elevate/SingleInstance/DetailsProvider
```

依赖方向：`app → ops → core`，`app → collect → core`；`ops` 与 `collect` 互不依赖（**禁的是库依赖**；ops 内部允许直调 OS API 做最小重枚举，见 §6 执行协议）。`collect/ops` 禁 include ImGui/UI 头。静态库强制边界：`stm_core`、`stm_collect`、`stm_ops`，目标 `SuperTaskMgr`(GUI)、`stm_selftest`(console)。

## 4. 数据契约（src/core/ProcData.h，摘录；完整以仓库为准）

```cpp
struct ProcKey { uint32_t pid = 0; uint64_t createTime = 0; };   // 身份=PID+创建时刻，防 PID 复用
inline bool operator<(const ProcKey&a,const ProcKey&b); bool operator==(...);
inline constexpr double kUnavail = std::numeric_limits<double>::quiet_NaN();     // UI 渲染 "—"
inline constexpr uint64_t kUnavailU64 = UINT64_MAX;

enum ProcFlag : uint32_t { PF_Elevated=1<<0, PF_Uwp=1<<1, PF_Wow64=1<<2, PF_ServiceHost=1<<3,
  PF_HasWindow=1<<4, PF_Protected=1<<5, PF_Suspended=1<<6, PF_AccessDenied=1<<7 }; // AccessDenied 为粘滞标志

struct ProcInfo {
  ProcKey key; uint32_t parentPid=0, sessionId=0;
  std::wstring name, path;                       // path 无权限时为空(诚实空)，非假路径
  uint64_t kernelTime=0, userTime=0;             // 累计 100ns（NtQSI，自校验门覆盖）
  double cpuPercent=kUnavail;                    // =Δ(kernel+user)/(tickSec×核数)×100，全核归一
  uint64_t workingSet=0;                         // NtQSI WorkingSetSize
  uint64_t privateWorkingSet=0;                  // PDH \Process(*)\Working Set - Private；PDH 不可用=kUnavailU64
  uint64_t commitBytes=0;                        // PrivateUsage（=私有提交；任务管理器"提交大小"口径）
  uint64_t ioReadBytes=0, ioWriteBytes=0;        // NtQSI 累计（自校验门覆盖）
  double diskBytesPerSec=kUnavail;               // NtQSI IO 差分/tickSec（口径=文件+网络+设备总和，UI 标注）
  double netBytesPerSec=kUnavail;                // 仅 ETW 开启时有值，否则 kUnavail
  double pageFaultsPerSec=kUnavail;              // PageFaultCount 差分（软+硬，文档化语义）
  double contextSwitchesPerSec=kUnavail;         // 线程 ContextSwitches 聚合差分
  uint32_t handles=0, threads=0, gdiObjects=0, userObjects=0;  // gdi/user=0 表示未取
  uint32_t flags=0; std::wstring windowTitle;    // 无窗口为空；每 5 tick 刷新一次
};

struct GpuAdapterInfo { std::wstring name; uint64_t luid=0; double utilPercent=kUnavail;
                        uint64_t memUsed=kUnavailU64, memTotal=kUnavailU64; bool virtualAdapter=false; };
struct GpuProcUsage { ProcKey key; uint64_t luid=0; double utilPercent=kUnavail;
                      uint64_t dedicatedBytes=kUnavailU64, sharedBytes=kUnavailU64; };

struct SystemInfo { double cpuTotalPercent=kUnavail; std::vector<double> perCorePercent; // 已减 Idle
  uint64_t physTotal=0, physAvail=0, commitTotal=0, commitLimit=0, kernPaged=0, kernNonpaged=0;
  uint32_t procCount=0, handleTotal=0, threadTotal=0;
  double diskReadBps=kUnavail, diskWriteBps=kUnavail, netRecvBps=kUnavail, netSendBps=kUnavail;
  double hardFaultsPerSec=kUnavail; std::vector<GpuAdapterInfo> gpus; double uptimeSec=0; };

struct Snapshot {
  uint64_t tickId=0; double tickSec=0; int64_t timestamp=0;
  bool degraded=false; std::wstring degradeReason;      // 兼容模式时 UI 显示
  uint32_t caps=0;                                      // CAP_NET_ETW=1…
  std::vector<ProcInfo> procs;                          // 按 pid 升序
  std::vector<GpuProcUsage> gpuProcs;                   // 与 procs 独立，按 (luid,pid)
  SystemInfo sys;
};

class SnapshotStore {  // mutex + shared_ptr<const Snapshot>；单写多读；构造即置空快照，Get() 永不返回 null
 public: std::shared_ptr<const Snapshot> Get() const; void Set(std::shared_ptr<const Snapshot>); };
```

自校验门（SelfCheckGate）：启动时取 3 个存活进程，将 NtQSI 读数与 GetProcessTimes / GetProcessMemoryInfo / GetProcessIoCounters / SystemHandleInformation 交叉比对 **5 项**（CPU 时间、WS、IO 字节、句柄数、线程数），任一超差（时间 ±1s、字节 ±25%、计数 ±10%）→ 整体降级 Toolhelp+PSAPI 慢路径（缺列显示"—"），UI 显示"兼容模式"。

## 5. 线程模型、队列契约与资源章程

| 线程 | 数 | 职责 | 预算 | 禁止 |
|---|---|---|---|---|
| UI | 1 | 消息循环、ImGui 帧、确认框、通知 drain | 空闲帧 ≤3ms | 阻塞调用 |
| 采集 | 1 | 周期快照 | tick ≤15ms @500 进程（NtQSI+PSAPI 路径）；GPU/PDH 通配符查询独立 2s 节奏、p95>10ms 自动降 4s 并告警 | UI API、高权限 OpenProcess 轮询 |
| 操作 | 1 | JobQueue 串行执行慢/破坏性操作 | — | UI API；CoInitializeEx(COM STA) 仅在本线程 |

队列契约（core/Jobs.h、core/Notifications.h）：
```cpp
using Job = std::function<void()>;            // JobQueue: Submit(Job)->uint64_t seq; PendingCount(); Shutdown(waitMs)
                                              // 退出协议：在途破坏性任务等待至多 2000ms 完成，未开始的丢弃并记日志
struct Notification { enum Kind { JobDone, JobFailed, Info, Warn } kind; uint64_t seq=0; std::wstring text; };
                                              // NotificationQueue: Push(n), Drain(std::vector<Notification>&)
```
JobQueue 护栏：签名校验仅允许固定盘路径（防网络路径超时占死队列）+ 同路径去重；UI 显示排队数。
资源章程（评审门禁，全模块遵守）：句柄一律 RAII（`core` 提供 `HandleGuard`）；PDH query 生命周期跟随其 Collector（实例集变化→重建 query）；ETW 会话启动即注册清理（RAII+进程退出 StopTrace，会话名含 PID 防孤儿）；OpsWorker 内 COM 走 `CoInitializeEx(STA)`+`CoUninitialize` 配对；ImGui→后端→D3D 逆序释放。自检清单见 01_review_V5 附 C，阶段 2/3 审查必查。

## 6. 破坏性操作执行协议（ops 层，安全关键）

1. **身份重验**：所有带 ProcKey 的 ops 函数先 `OpenProcess` → `GetProcessTimes` 比对 createTime（±1s），不匹配即报"已退出或 PID 复用"拒执行。
2. **自含枚举**：ops 允许直调 NtQSI/Toolhelp 做最小枚举（不依赖 stm_collect 库）。`CollectTreeMembers(rootProcKey, out)` 为纯函数（输入快照缓冲、输出后代 ProcKey 列表，BFS+父链 createTime 校验防父 PID 复用误收）——单测覆盖。
3. **成员级防线**：树杀逐成员过保护名单，受保护成员**跳过并如实报告**（不整树拒绝也不放行）。
4. **两段式树杀接口**（UI 先 Plan 显示"预计 N 个（执行时可能变化）"，确认后执行）：
```cpp
namespace ops {
bool PlanTerminateTree(const ProcKey& root, std::vector<ProcKey>* out, std::wstring* err);
struct TreeResult { int planned=0, terminated=0, failed=0, skippedProtected=0; std::wstring firstError; };
bool TerminateTree(const ProcKey& root, TreeResult* out, std::wstring* err);   // 执行时重快照, leaf-first, 逐个重验
bool TerminateProcessById(const ProcKey& k, std::wstring* err);
bool TrimWorkingSet(const ProcKey& k, std::wstring* err);
bool PurgeStandbyList(std::wstring* err);
std::wstring ProtectedReason(const ProcKey& k);   // 非空=在保护名单
}
```
5. 服务宿主（PF_ServiceHost）终止：确认框红字警告"服务宿主进程，强杀会连坐同宿主服务"；阶段 2 显示通用警告，阶段 3 接 SCM 映射列出具体服务名。

## 7. 提权模型专章（1A）

- manifest `asInvoker` + PerMonitorV2 + longPathAware；`Elevate::RelaunchAsAdmin(args)`：`ShellExecuteExW(runas)`，`ERROR_CANCELLED` 静默回退；**返回 true=调用方应立即退出**。
- **重启协议（无事件版）**：旧实例把会话状态原子写入 session.json（temp 文件 + `MoveFileExW(REPLACE_EXISTING)`；内容白名单：页签 id、选中 ProcKey、排序键/方向、窗口 rect、刷新间隔），随即退出释放互斥体；新实例 `CreateMutex`，`ERROR_ALREADY_EXISTS` 则最多等 **1000ms**，仍拿不到→提示"已有实例"退出；拿到即证明旧实例已终结 → 读 session.json（存在、可解析、ts<60s 才恢复），损坏自然降级全新启动。
- 功能×权限矩阵（驱动 UI"需提权"徽标）：
  | 功能 | 普通 | 提权 |
  |---|---|---|
  | 枚举/全指标/PDH/TCP-UDP 表/HKCU 启动项/当前用户启动文件夹 | ✅ | ✅ |
  | 他人进程路径/内存/命令行、EmptyWorkingSet、树杀、服务启停、HKLM Run 写、计划任务系统文件夹改、SMART、ACPI 热区、ETW 增强、模块列表 | ⚠️降级 | ✅ |
  | 驱动列表（24H2+ 需 SeDebug） | ❌ | ✅ |
- SeDebugPrivilege 按需启用、用后即释；每次特权启用记日志（透明可审计）；自身不自启动、不留服务、无监听端口（链接表不含 ws2_32 监听用途——ETW/iphlpapi 除外并声明）。

## 8. UI 层设计

- 框架：工具条（间隔/暂停/提权/搜索）+ 左侧 `IPage` 静态注册页签（阶段 2：进程、性能；阶段 3：网络、启动项、服务、驱动、传感器）+ 状态栏（自身 CPU/WS/tick 耗时自省）。
- 进程页列（与 §4 契约一一对应）：名称 | PID | CPU% | 内存(私有工作集) | 提交 | 磁盘 | 网络 | 硬故障/s | 句柄 | 线程 | 上下文切换/s | 徽标(提权/UWP/WOW64/服务) | 描述(文件版本，按需)。排序：键仅用户设定；每 tick 对行索引 `stable_sort`（原始值比较、中文列 CompareStringEx、pid 升序破平局、过滤先行）；兼容模式缺列显示"—"。
- 选中与详情：选中=ProcKey；快照刷新后按 pid 二分+createTime 校验，丢失则详情面板冻结显示"已退出"；确认框打开瞬间锁定 ProcKey 副本。
- DetailsProvider（按需+缓存，走 JobQueue；缓存键 path+size+mtime）：
```cpp
struct ProcessDetails { std::wstring path, cmdLine, userName, companyName, fileDescription, version;
                        SigState sig; uint32_t gdi=0, user=0; bool cmdLineAvail=false; };
class DetailsProvider { public: void Request(const ProcKey&, DetailKind);  // Kind: Signature|CmdLine|UserInfo|GuiObjects|Modules
                        const ProcessDetails* Peek(const ProcKey&) const; };
```
- 确认对话框：模态居中；单杀=名称/PID/路径/用户；树杀=PlanTerminateTree 结果"预计 N 个（执行时可能变化）"+服务宿主红字警告；内存清理=诚实说明文案（"工作集页换出后再访问会缺页，短期可能变卡；清待机列表仅释放系统缓存，不回收进程内存"）；保护名单进程菜单禁用。
- 图表：ImPlot 按时间窗（120s）滚动；性能页 CPU(总+每核)/内存(物理+提交)/磁盘/网络(+GPU，阶段 3)；告警(阶段 3 可选)=阈值+托盘气泡，默认关。悬浮窗：master 分支 imgui 无多视口（已实证），暂缓；若阶段 3 需要则以独立 Win32 顶层窗口方案评估，或切换 docking 分支（成本另评）。
- 主题：暗色默认；中文 msyh.ttc 动态字体（1.92）；WM_DPICHANGED 处理。
- 数字规范：kUnavail→"—"；字节/速率 KiB/MiB 本地化；"0"仅表示真实为零；首 tick 差分字段为 kUnavail。

## 9. 日志、错误、配置

- Log：级别 Debug/Info/Warn/Error → 滚动文件 + Debug 构建 OutputDebugString；**禁记命令行、窗口标题等敏感值**（可记路径与 PID）；tick 逐帧不记。
- Err：Win32→HRESULT 统一，`Err::LastHr()`；破坏性操作错误带出参上 UI；异常不跨模块边界。
- Cfg：手写最小 JSON（无第三方）；键见 §7 白名单 + 主题/列布局/ETW 开关/告警阈值。

## 10. 性能预算（阶段 4 门禁）

| 项 | 预算 | 测法 |
|---|---|---|
| 采集 tick(NtQSI+PSAPI 路径) | p95 ≤15ms @500 进程 | selftest 统计 |
| GPU/PDH 通配符查询 | 独立 2s 节奏；p95>10ms 自动降 4s | 运行时自省+状态栏 |
| UI 空闲帧 | ≤3ms；最小化 2s 间隔 | 帧计时叠加 |
| 自身内存/启动/磁盘 | 【阶段 4 修订（实测）】空载 WS ≤150MB 且无增长趋势（实测基线 ≈124MB：D3D11 运行时/驱动 + 动态字体图集 + 堆，30s 零增长）；泄漏门禁=长时间运行增长 <5MB；启动 <1.3s 到主窗（实测 1.26s 含 30 帧 vsync）；日志滚动 ≤3×1MB | 对照+日志时间戳 |
